===========================================
SECTION 2: AUTOMATIC TOKEN REFRESH SYSTEM
===========================================

PROBLEM:
When access tokens expired, users had to manually refresh the page to get a new token. 
This caused:
- API calls to fail with 401/403 errors
- Socket connections to disconnect
- Poor user experience requiring manual page refresh

SOLUTION:
Implemented a centralized automatic token refresh system that works for both HTTP requests and WebSocket connections.

===========================================
NEW FILES CREATED:
===========================================

1. /frontend/src/utils/fetchWithAuth.ts
   PURPOSE: Centralized fetch wrapper with automatic token refresh
   
   FUNCTIONALITY:
   - Wraps native fetch() with auth handling
   - Automatically includes credentials: 'include' (sends cookies)
   - Intercepts 401/403 HTTP errors
   - Calls /api/auth/refresh endpoint to get new access token
   - Retries the original request with new token
   - Redirects to /login if refresh fails
   - Transparent to the caller - works exactly like fetch()
   
   EXPORT: fetchWithAuth(url, options)

2. /frontend/src/utils/socketAuthHandler.ts
   PURPOSE: Socket.IO authentication error handler
   
   FUNCTIONALITY:
   - Monitors socket connect_error events for auth issues
   - Listens for 'unauthorized' events from server
   - Automatically refreshes token when auth errors occur
   - Reconnects socket after successful refresh
   - Redirects to /login if refresh fails
   
   EXPORT: setupSocketAuthHandler(socket)

HOW TOKEN REFRESH WORKS:

1. HTTP Requests Flow:
   ┌─────────────────────┐
   │ Component makes     │
   │ API call using      │
   │ fetchWithAuth()     │
   └──────────┬──────────┘
              │
              ▼
   ┌─────────────────────┐
   │ Request sent with   │
   │ cookies (tokens)    │
   └──────────┬──────────┘
              │
              ▼
   ┌─────────────────────┐
   │ Server responds     │
   │ 200 OK or 401/403   │
   └──────────┬──────────┘
              │
              ▼
        Is 401/403?
              │
         Yes  │  No
              ▼     └──────────────┐
   ┌─────────────────────┐         │
   │ Call /api/auth/     │         │
   │ refresh endpoint    │         │
   └──────────┬──────────┘         │
              │                    │
              ▼                    │
       Refresh OK?                 │
              │                    │
         Yes  │  No                │
              ▼     │               │
   ┌─────────────────────┐         │
   │ Retry original      │         │
   │ request             │         │
   └──────────┬──────────┘         │
              │                    │
              ▼                    │
              └────────────────────┤
                                   │
                                   ▼
              ┌─────────────────────┐
              │ Return response     │
              │ to component        │
              └─────────────────────┘

2. Socket Connections Flow:
   ┌─────────────────────┐
   │ Socket connects     │

===========================================
BENEFITS OF THIS IMPLEMENTATION:
===========================================

1. SEAMLESS USER EXPERIENCE:
   - No more manual page refreshes needed
   - Token refresh happens in background
   - User doesn't notice when tokens expire
   - Continuous gameplay without interruption

2. CENTRALIZED LOGIC:
   - Single place to handle token refresh (fetchWithAuth)
   - Easy to maintain and update
   - Consistent behavior across entire app

3. AUTOMATIC COVERAGE:
   - All API calls protected
   - All socket connections protected
   - No need to remember to add refresh logic

4. SECURITY:
   - Tokens still expire (good security practice)
   - Refresh only happens when needed
   - Automatic logout if refresh fails

5. DEVELOPER FRIENDLY:
   - Simple API: just use fetchWithAuth() instead of fetch()
   - Works like native fetch()
   - One-line socket protection: setupSocketAuthHandler(socket)

===========================================
USAGE EXAMPLES:
===========================================

FOR HTTP REQUESTS:
Before:
  const response = await fetch('/api/endpoint', {
    credentials: 'include',
  });

After:
  const response = await fetchWithAuth('/api/endpoint');

FOR SOCKET CONNECTIONS:
Before:
  const socket = io({
    withCredentials: true,
  });

After:
  const socket = io({
    withCredentials: true,
  });
  setupSocketAuthHandler(socket);
